The cooperative row selects `threading=multi`; it does not claim CPU parallelism
or concurrent access to a stream. Socket tests drive one context and real loopback
peers. SDK 34 cooperative components in this test were rejected by Wasmtime 47.0.3
with an end-of-file parse diagnostic; those files passed with 49.0.3, and
the current rebuilt suite passed with 50.0.1.
Select the intended runtime explicitly through `PATH` before running B2.

The commands below assume the toolsets in `.local/user-config.jam`. The local
build directories isolate this evidence from other work. A leading `-a` forces
compilation and execution. These focused reproduction commands select the same
Beast targets exercised by the collection-wide upgrade. The complete requests and
logs of that rerun are in `.local/wasmtime-50-validation/`: `wasip2-single-all.log`,
`wasip3-single-all.log` and `wasip3-coop-all.log`.

[source,bash]
----
unset CPATH CPLUS_INCLUDE_PATH C_INCLUDE_PATH
export PATH="$PWD/.local/wasmtime-50/wasmtime:$PATH"
b2 --user-config=.local/user-config.jam --build-dir=.local/beast-implementation/native-final -a variant=release exception-handling=on,off libs/beast/test libs/beast/example
b2 --user-config=.local/user-config.jam --build-dir=.local/beast-implementation/native-multi -a variant=release threading=multi exception-handling=on,off libs/beast/test libs/beast/example
b2 --user-config=.local/user-config.jam --build-dir=.local/beast-implementation/p2-final -a toolset=clang-wasip2 variant=release exception-handling=on,off testing.launcher=wasmtime libs/beast/test libs/beast/example
b2 --user-config=.local/user-config.jam --build-dir=.local/beast-implementation/p3-final -a toolset=clang-wasip3 variant=release exception-handling=on,off testing.launcher=tools/boost/asio-wasip3/run.sh libs/beast/test libs/beast/example
b2 --user-config=.local/user-config.jam --build-dir=.local/beast-implementation/p3-cooperative -a toolset=clang-wasip3 variant=release threading=multi exception-handling=off testing.launcher=tools/boost/asio-wasip3/run.sh libs/beast/test libs/beast/example
b2 --user-config=.local/user-config.jam --build-dir=.local/beast-implementation/browser-final -a toolset=emscripten variant=release exception-handling=on,off libs/beast/test libs/beast/example
----

default construction with a defaultable layer, same-type move, conversion from a
specific executor to `any_io_executor`, and `rebind_executor` retaining the facade.

`WEBCPP_TEST_UPSTREAM_BEAST`, then compared by B2 for each target. The guide's code
and output include those source files directly. MrDocs generated the API reference
and the AsciiDoc source and rendered-page checks passed locally.
